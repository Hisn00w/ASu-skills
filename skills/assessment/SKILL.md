# /assessment：笔试与测评准备

把笔试和在线测评从「海投后的随机应变」变成「按题型、按岗位的针对性准备」。目标是先帮用户识别接下来要面对的是哪一类测评，再按类别给出准备方案，而不是无差别刷题。

## 输入

优先读取当前对话已有材料，不要求用户重复提供：

1. 目标岗位与 JD（决定技术笔试的考点范围）；
2. 收到的测评链接、邮件说明或测评平台名称（如北森、SHL、牛客、赛码等）；
3. 已有的时间安排：测评截止时间、可用备考天数。

没有测评说明时，可以按目标岗位类型推断常见测评组合，但必须标明这是推断而非事实。

## 测评类型识别

先确认用户面对的是哪一类，再给对应方案，三类不要混为一谈：

- **技术笔试**：算法题、编程语言八股、数据库 / 网络 / 操作系统、系统设计；
- **行测（认知能力测评）**：言语理解、判断推理、数量关系、资料分析；
- **性格 / 职业测评**：北森、SHL、大五、MBTI 等，用于岗位匹配与筛选。

## 各类型应对

### 技术笔试
- 按 JD 技术栈和岗位级别出题，从高频考点（数据结构、算法、语言特性、数据库）到公司常见题型；
- 每道题给「题目 → 思路 → 最优解 → 复杂度 → 易错点」；
- 按用户掌握程度分轮推进：先扫盲，再专项，最后限时模拟。

### 行测
- 按言语 / 判断 / 数量 / 资料四个板块梳理题型与解法套路；
- 数量与资料分析重在「限时取舍」，给出时间分配建议，不追求每题都做。

### 性格测评
- 明确这不是「考试」，核心是「一致性 + 岗位匹配」；
- 给出答题原则：保持前后一致、按目标岗位需要的画像作答但不极端化、避免反复横跳；
- 提醒常见淘汰信号（责任感、抗压、团队协作等维度的异常低分），但不教用户造假。

## 默认交付

按需输出：

1. 测评类型判断与准备优先级；
2. 针对性题库 / 题型清单（技术笔试）或板块攻略（行测）或答题原则（性格测评）；
3. 一道到多道例题详解，或一次限时模拟；
4. 备考时间分配建议；
5. 后续交接（仅在用户需要时生成）。

## 路由与交接

- 需要把项目 / 经历讲清楚以应对技术面：交给 `/project-guide` 或 `/interview`；
- 需要记录测评 / 笔试结果与状态：交给 `/offer`；
- 测评暴露出的能力短板需要补经历或证据：交给 `/contributor` 或 `/great-resume`。

## 事实边界

- 不声称掌握某公司「内部真题」，只提供公开常见题型和题型规律；
- 不替用户完成需要真人参加的测评，也不帮用户绕过平台防作弊机制；
- 性格测评只讲通用原则与风险提示，不教唆造假或捏造人格画像。
