# /offer：秋招进度管理与 Offer 决策

把零散的招聘邮件、截图和聊天记录整理成可复盘的求职漏斗，记录公司、岗位、日期、状态、下一步和备注。手上出现多个 Offer 时，在同一个技能内切换到决策模式。不得把申请编号、密码、验证码或无关个人信息写入公开资源。

## 两种工作模式

| 模式 | 触发 | 主要交付 |
| --- | --- | --- |
| 信息管理 | 记录投递、测评、面试、Offer 状态，整理招聘邮件 | 求职进度表、状态变化、下一步清单 |
| 比较与决策 | 手上有一个以上 Offer，需要比较、排序、谈薪 | Offer 对照表、加权建议、谈判要点 |

两种模式共用同一份 Offer 记录：进入决策模式时先读取进度表里已有的公司、岗位、城市、薪资和福利，不重复追问用户；决策结论需要留档时再写回进度表。用户只要求“记录一下”时不进入决策模式，只问“选哪个”时也不要求先建表。

## 信息管理模式

### 资源定位

ASu 资源支持两种布局，按以下顺序定位：Claude Code 安装布局使用 `../../assets/asu/` 与 `../../references/asu/`；仓库插件布局使用 `../../assets/` 与 `../../references/`。每个候选均为一对 assets/references 目录：仅当 assets 目录同时包含 `application-tracker.html` 和 `application-tracker-overview.svg`，且对应 references 目录包含 `email-monitoring.md` 时才使用该目录对，避免误用其他 skill 的资源。`application-tracker.html` 是可编辑的求职进度表，`application-tracker-overview.svg` 是预览图。

如果 skill 被单独复制到其他目录，先从当前 skill 目录向上依次定位 `assets/asu/`、`references/asu/` 与仓库插件的 `assets/`、`references/`，不要重新制作已有资源。

### 工作流程

1. 从用户提供的邮件、招聘网站或截图中提取日期、公司、岗位、当前状态、下一步和必要备注。
2. 合并同一公司同一岗位的重复记录；后来的测评、面试、拒信或 Offer 状态覆盖早期的“已投递”。
3. 只在有证据时更新状态；普通自动回执不能推断为面试或 Offer，证据不足标记为“待确认”。
4. 用户未指定文件位置时，将 `application-tracker.html` 复制到桌面，并返回生成文件的绝对路径。
5. 用户要求查看邮箱或每日检查时，使用浏览器处理；登录、密码、MFA、验证码和 CAPTCHA 由用户完成，不代为保存。
6. 用户需要同时制作简历文件时，转入 `/make-resume`；需要提升经历时，转入 `/great-resume`。

### 状态规范

默认状态包括：已投递、筛选中、测评中、面试、Offer、拒绝/已结束、待确认。每次更新尽量写明证据来源和下一步动作，便于后续复盘。

## 比较与决策模式

1. 先确认 Offer 数量和各维度关键字段是否齐全；缺失字段列成“待确认”，不用行业惯例或平均值替用户补数。
2. 按 [Offer 对比决策流程](references/offer-decision.md) 拆解薪资结构、成长空间、业务与团队、稳定性与风险、个人成本。
3. 只使用用户给出的权重和统一评分尺度，缺失信息不按 0 分参与加权。
4. 输出“选 A 放弃什么、选 B 放弃什么”的对照，不给替用户拍板的绝对推荐。
5. 用户确认选择后，把结论、待确认项和下一步写回进度表。

决策流程较长，具体维度、评分尺度、缺失信息处理和输出模板都在 [references/offer-decision.md](references/offer-decision.md)，按需读取；用户只问单个 Offer 的薪资构成时，只读取其中对应的小节。

## 事实边界

- 只在有证据时更新状态；普通自动回执不能推断为面试或 Offer，证据不足标记为“待确认”。
- 加权评分统一使用同一评分尺度和评分依据，每条评分都要能回指 Offer 原文、HR 回复或用户陈述；无法回指的维度不得打分。
- 缺失信息标记为“待确认”，单独列出并说明它对结论的影响，不能直接按 0 分处理，也不能混入加权总分。
- 实习转正概率只能引用 HR 明确说明或用户提供的数据，不得让模型自行估算；没有可靠数据时作为不确定因素单独分析，不给百分比。
- 不给“某公司值不值得去”的绝对判断，只提供可比较维度和用户自己的权衡。
- 不把期权、股票按面值折算成现金，也不替用户估算公司估值。
- 不把用户的真实求职记录写进 skill 的模板或 README。

## 默认交付

- 信息管理模式：进度表文件、已识别记录摘要、状态变化、下一步清单和缺失信息。
- 比较与决策模式：Offer 对照表、缺失与待确认字段清单、按用户权重计算的建议、谈判要点，以及需要交接的其他技能。

## 路由与交接

- 决策完成后需要准备入职或实习复盘：转入 `/evidence-recap`；
- 选择前想评估岗位长期匹配度：转入 `/job-match`；
- 需要针对某个 Offer 重做简历：转入 `/great-resume` 和 `/make-resume`。
