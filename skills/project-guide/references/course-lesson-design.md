# 单课讲解规范

先读取目标课程的大纲、前后边界和当前实现。保留课程编号与主题，将该课展开为可以直接学习的内容；如果主题已被源码变更废弃，说明差异与调整建议，不强行套用旧流程。

## 教学顺序

1. **场景与目标**：说明什么触发本流程、学习者最终应能解释什么，并补充最少量前置概念。
2. **主链与阅读顺序**：先展示完整主链，再列真实文件和符号的必读顺序，区分选读与暂缓源码。
3. **沿流程带读**：跟随调用顺序解释关键输入、下一调用、状态变化和返回位置。只引用解释行为所需的短代码片段。
4. **重要分支**：在分支发生的位置解释条件与结果。异步边界分别说明请求返回和后台结束。
5. **完整流程串联**：用一个具体输入重走入口到结果，再连接源码已经实现的失败、有效恢复和清理路径。

不同分支作为同一场景的变体讲解，不能串成一次不可能发生的执行。没有重试、删除或清理实现时，说明流程止于何处，不补造这些能力。只有当幂等或对象身份影响当前分支时，才解释重复提交、重试原对象和创建新对象之间的实际区别。

## 完成标准

- 主要章节沿真实调用或事件顺序展开；
- 每个结论可以定位到代码、测试或明确的配置证据；
- 设计取舍和算法细节只在影响流程理解或用户要求时补充；
- 最后一节包含简短流程回顾和一项由学习者自行复述的任务，不要求运行项目；
- 未确认的动态目标和外部依赖边界有明确标记；
- 本课状态更新为 `已展开`，其他课程保持原样。
