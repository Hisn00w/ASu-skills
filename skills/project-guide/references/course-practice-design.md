# 配套练习规范

读取 `tutorial.md` 对应课程。题目只检验已经讲解的流程与知识。课程仍处于大纲状态时，只能生成阅读引导题；用户要求课后理解题时，先说明需要展开该课，不能把未讲内容当作已学知识。

## 题目结构

`practice.md` 按课程相同编号和标题组织，并注明对应课程状态。每题围绕一个独立回答目标，从项目场景出发，要求学习者用源码证据解释因果关系，例如：

- 输入从哪个入口开始，经过哪些关键调用，最终在哪里返回或改变状态；
- 已讲分支发生失败时，哪些操作已经完成，调用方或用户会看到什么；
- 课程已经讲过恢复路径时，什么条件允许恢复，它与重新提交有什么区别。

以上内容仅用于说明题型，具体问题必须来自对应课程。将同一流程的细节作为自然追问；答案和主要证据高度重合的题目应合并。题量由独立回答目标决定，不设置固定数量。

## 表达边界

- 默认只写问题和必要的回答要求，不附标准答案；用户明确要求解析时可以提供。
- 题目检验项目流程与职责理解，不要求背诵字段拼写，也不默认布置编码、测试集设计或重构任务。
- 只有课程已经讲解设计原因，或用户明确要求时，才加入架构取舍题。
- 用户提交答案后，根据本题和源码指出已讲清、遗漏和错误部分，不根据一道题推断整个项目的掌握程度。

## 局部更新检查

- 新增或更新的课程编号、标题与 `tutorial.md` 一致；
- 题目没有超出对应课程范围；
- 其他课程、已有题目和用户答案保持原样；
- 只有用户要求同步时，才随课程重排调整相应练习。
