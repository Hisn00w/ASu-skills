# 课程大纲规范

先检查项目入口、主要功能和模块之间的依赖，用一条代表性端到端流程建立项目全貌，再将其他独立行为排入课程。章节数量来自实际学习目标，不按文件、类或知识点计数。

每课应能回答一个具体项目问题，例如一次请求如何被处理、后台任务怎样从提交走到终态。辅助函数、配置和状态字段放在所属流程中；相邻课程若需要同一段主要证据回答同一个问题，应合并。复杂流程可以分层：先走通公开接口，后续课程再深入能够独立学习的子流程。

## tutorial.md 结构

文件开头写明：

- 项目用途与本次学习目标；
- 源码版本和影响结论的本地改动；
- 学习所需的前置基础；
- 本次覆盖范围与尚未覆盖的模块。

每课必须包含：

1. 稳定的编号、标题与读完能回答的问题；
2. `触发 → 入口 → 关键调用或事件 → 重要分支 → 结果` 的主链；
3. 编号的必读路径与符号，每步注明输入、下一步和输出；
4. 用于验证行为的选读证据；
5. 暂缓阅读的相邻实现，以及由哪一课负责；
6. `大纲` 状态，用于区别已经展开的课程。

纯配置或声明式项目按加载、解析、规则生效到可见结果组织，明确可访问源码的边界。不得为了填满模板补造生命周期阶段，也不得把目录或无序文件清单当作源码阅读路线。

## 大纲检查

- 主要功能是否有明确归属；
- 课程是否按学习依赖排序；
- 学习者是否能按路线找到真实源码；
- 相邻课程是否重复同一核心流程；
- 是否列出未覆盖模块与不确定边界；
- 已展开课程是否在用户未要求重写时保持原文。
