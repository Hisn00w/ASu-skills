# 复盘与弱项复练

Review 或 Retry 模式读取本文件。

## 复盘输出

复盘以会话账本和真实回答为依据：

```text
## Resume Mastery Review

### 本轮范围
- 岗位 / 轮次：……
- 已覆盖：……
- 未覆盖：……

### 已验证
- Claim：……
  证据：用户说明了……

### 部分验证
- Claim：……
  已有证据：……
  缺口：……

### 未验证或存在矛盾
- Claim：……
  依据：……
  处理：补事实 / 补知识 / 降低表述

### 面试前行动
1. ……

### 复练队列
1. Claim：……
   下一题型：变体 / 反事实 / 故障 / 指标口径
```

不得因为用户只回答了少量问题就推断整份简历掌握程度。没有证据支持时使用 `未覆盖`，而不是低分。

## 优先级

按以下顺序安排面试前行动：

1. 与 JD 高相关且存在虚假或矛盾风险的 Claim；
2. 强 Ownership、Metric 和 Result Claim；
3. 面试中已经暴露的技术理解缺口；
4. 表达结构问题；
5. 低相关补充知识。

## 复练规则

复练只选择 `partial`、`unverified` 或 `contradictory` Claim。不要原题原样重复，优先使用：

- 变体题：换一个输入或限制；
- 反事实题：如果候选条件变化，方案是否仍成立；
- 故障题：给出异常现象，要求定位；
- 证据题：要求说明代码、数据、日志或统计口径；
- 压缩表达：用 60 秒重新讲清同一 Claim。

比较复练前后新增证据：

```text
上次缺口：无法说明指标基线。
本次新增：说明了优化前口径、样本周期和数据来源。
结果：从部分验证更新为已验证。
```

如果用户只是背出上次建议但仍无法处理变体题，不升级为 `verified`。

## 简历表述处理

对高风险表述给三种选择：

1. **保留**：事实、个人边界和证据充分；
2. **降低强度**：项目真实，但“主导、架构、显著提升”等词证据不足；
3. **暂缓使用**：关键事实无法确认或与前文矛盾。

可以帮助用户组织真实答案，但不生成不存在的工作经历、数据、代码细节或业务结果。
