# /offer-decision：Offer 对比决策

把「选哪个 Offer」从凭感觉变成可比较、可复核的决策过程。目标不是替用户做决定，而是把每个 Offer 拆成可量化的维度，帮助用户看清自己真正在意什么、每个选择放弃的是什么。

## 输入

1. 两个或以上 Offer 的关键信息：公司、岗位、城市、薪资结构、试用期、福利；
2. 可选的个人约束：家庭所在地、职业方向偏好、风险承受能力。

信息不全时，先列出「影响决策但缺失」的字段再分析，不用平均值或行业惯例替用户补数。

## 分析维度

按以下维度逐项拆解，区分「可量化事实」与「个人偏好」：

1. **薪资结构**：月薪、年终、股票 / 期权、签字费、公积金基数与比例、涨薪机制；区分「总包」与「到手」；
2. **成长空间**：业务阶段、团队规模、技术栈、晋升通道、转正机会（实习）；
3. **业务与团队**：业务是否核心、直属 leader、团队氛围、加班强度；
4. **稳定性与风险**：公司经营状况、裁员历史、行业景气度；
5. **个人成本**：城市与通勤、落户、生活成本、家庭因素。

## 决策方法

1. 把每个维度拆成「事实 + 用户评分」，事实要能回指 Offer 原文或用户陈述；
2. 让用户给每个维度的「权重」打分，再算加权结果；权重由用户定，不由 skill 代定；
3. 输出「如果选 A 你放弃了什么、如果选 B 你放弃了什么」的对照，而不是只给一个总分；
4. 涉及实习 Offer 时，把「转正概率」单独列为高权重项，并提示需要向 HR 确认的信息。

## 默认交付

1. Offer 信息对照表（维度 × 各 Offer 事实）；
2. 缺失但影响决策的字段清单；
3. 用户加权后的决策建议（含不确定项）；
4. 谈判要点：可谈的项目（薪资、签字费、入职时间、转正条件）与不建议谈的；
5. 后续交接（仅在用户需要时生成）。

## 路由与交接

- 需要记录最终选择与 Offer 状态：交给 `/offer`；
- 决定接受后需要准备入职 / 实习复盘：交给 `/evidence-recap`；
- 选择前想评估岗位长期匹配度：交给 `/job-match`。

## 事实边界

- 不给「某公司值不值得去」的绝对判断，只提供可比较维度和用户自己的权衡；
- 不把期权 / 股票按面值折算成现金，也不替用户估算公司估值；
- 薪资、福利等事实以 Offer 原文和用户陈述为准，缺失时标注「待确认」，不用公开数据猜测。
