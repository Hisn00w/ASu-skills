## 第 1 课：一次 check 如何从描述输入走到检查结果

对应课程状态：已展开。

回答要求：用自己的话解释因果关系，并指出 [scripts/project_guide.py](../../scripts/project_guide.py) 中的函数及关键条件作为证据。无需运行项目、编写代码或背诵字段名。

### 题 1：命令如何找到处理函数

用户执行 `python scripts/project_guide.py check -d "太短了" --json`。请从脚本入口追踪到 `command_check`，说明 `args.func` 是在哪里绑定的、解析结果怎样传入处理函数。最后说明处理函数返回的整数如何成为进程退出码，以及测试直接调用 `main([...])` 有何不同。

### 题 2：描述来源会不会自动回退

用户同时传入 `--file material.txt` 和一段非空 `-d` 描述。分别考虑文件含有效文字、文件只有空白、文件不存在三种情况：实际读取哪个来源，是否进入 `analyze_input`，空白或读取失败后是否尝试 `-d`？再解释 `-d "   "` 与空字符串参数在来源选择上为何不同，以及未提供任何来源时 stdin 何时读完。

### 题 3：通过检查究竟说明了什么

假设两段描述分别为 39 和 40 个字符，均未命中任何关键词，技术栈和岗位均未提供。请比较必须补齐项、建议、备注和 `ok` 的变化，说明为什么仍有建议也能通过。随后说明无关键词描述从 79 增至 80 个字符时，哪一组追问会改变，以及“通过”能否证明项目经历真实完整。

### 题 4：调用方应该读取哪个结果

对非空短描述分别选择文本和 JSON 输出，再与仅含空格的描述对比。请说明各场景写入 stdout 还是 stderr、是否有结构化检查结果、返回码是什么。若自动化调用方只根据退出码判断材料是否达标，会错判哪种情况？引用输出分支和提前返回位置说明。

### 题 5：失败停在哪一步

分别考虑缺少子命令、读取描述文件发生异常、读取后描述为空三个场景。说明各自停在调用链的哪一处，哪些后续操作还未发生。源码是否存在自动重试、保存进度或补充材料后继续执行的机制？若用户想补充材料再检查，应如何理解下一次调用与本次调用的关系？
