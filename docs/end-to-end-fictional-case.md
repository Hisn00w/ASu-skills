# 端到端虚构案例：从课程项目到求职闭环

> 本文中的人物、学校、项目、仓库、公司、联系方式和数据均为虚构示例，仅用于展示 ASu-skills 各入口如何交接。示例链接使用 `example.com`，不对应真实贡献。

## 1. 原始情况

林舟是星海大学计算机科学专业大三学生，目标岗位是 **AI 应用工程师实习生**。他没有正式实习，现有材料如下：

| 类型 | 原始材料 | 当前问题 |
| --- | --- | --- |
| 课程项目 | 用 Python 和一个大模型 API 做过会议纪要 Demo | 只会描述“调用 API”，没有系统边界和结果证据 |
| 开源经历 | 没有已合并 PR | 缺少公开协作证据 |
| 简历 | 一页 Word，项目按时间排列 | 没有目标岗位定位，项目要点偏功能罗列 |
| 求职进度 | 还未开始投递 | 没有记录方式 |

真实短板也需要保留：

- 没有生产环境部署经历；
- 没有大规模模型训练经验；
- 课程项目只有 3 人使用过，没有公开用户量；
- 英语成绩和毕业时间尚未确认。

建议工作流：

```text
/contributor → /asu → /resume → /interview → /offer
```

## 2. `/contributor`：补一条可验证的公开协作证据

### 输入

```text
目标岗位：AI 应用工程师实习生
技术栈：Python、TypeScript
每周可投入：4 小时
先找一条容易验证的小贡献，展示 diff 后再决定是否提交。
```

### 处理目标

`/contributor` 先只读搜索近期活跃、贡献规则清楚的项目，排除已有重复 Issue/PR，再准备本地最小改动。示例候选为：

| 字段 | 示例 |
| --- | --- |
| 仓库 | `OpenPromptLab/guidebook`（虚构） |
| 问题 | Python 快速开始示例缺少环境变量说明 |
| 拟修改 | 补充 `.env` 配置步骤和一条运行验证命令 |
| 验证 | 按文档从空目录完成示例运行；检查 Markdown |
| 外部写操作 | 尚未执行，等待用户确认 |

用户确认 diff、PR 标题和正文后，才执行 fork、push 和 PR。假设 PR 最终被合并，得到以下证据卡：

```yaml
repository: OpenPromptLab/guidebook
pr_url: https://example.com/OpenPromptLab/guidebook/pull/18
status: merged
merged_at: 2026-09-03
problem: Python 快速开始缺少环境变量配置说明
contribution:
  - 补充 .env 配置步骤
  - 增加可复现的运行验证命令
verification:
  - 从空目录完成快速开始流程
  - Markdown 预览通过
boundary: 仅修改文档，不声称参与核心模型开发
```

### 输出与交接

交给 `/asu` 的不是“开源大佬”头衔，而是可核验的事实：一个已合并 PR、一处具体问题、两项实际修改和验证过程。

## 3. `/asu`：从动作整理为岗位相关叙事

### 输入

- 目标岗位：AI 应用工程师实习生；
- 会议纪要课程项目原始说明；
- `/contributor` 生成的已合并 PR 证据卡；
- 真实短板和待确认字段。

### 处理目标

先建立定位，再按“动作 → 系统能力 → 业务价值 → 结果证据 → 个人边界”改写。

#### 一句话定位

> 具备 Python 与 TypeScript 工程基础的 AI 应用方向本科生，完成过带结构化输出和人工校验流程的会议纪要 Demo，并有已合并的开源文档贡献。

#### 项目改写片段

原始说法：

> 调用大模型 API 做了一个会议纪要网站。

建议写法：

> 搭建会议纪要原型，将音频转写结果经过提示模板生成议题、结论和待办三类结构化字段；负责 Python 服务、TypeScript 页面和失败结果的人工修订入口，完成 3 名课程组成员的演示验证。项目为课程 Demo，尚未进入生产环境。

#### 开源贡献改写片段

> 为开源项目的 Python 快速开始补充环境变量配置与可复现验证命令，完成从空目录运行检查；PR 已被合并。贡献范围为文档与开发者体验，不涉及核心模型代码。

#### 主张审计

| 原始说法 | 建议写法 | 事实证据 | 个人边界 | 状态 |
| --- | --- | --- | --- | --- |
| 做过 AI 产品 | 完成会议纪要课程原型 | 课程演示、代码、3 名成员试用 | 非生产系统 | 已确认 |
| 有开源经验 | 已合并一项快速开始文档改进 | PR 链接、review、merge 记录 | 不涉及核心代码 | 已确认 |
| 熟悉大模型应用 | 有 API 接入、结构化输出和人工修订实践 | 代码与演示 | 不等同于训练或 AI Infra 经验 | 已确认 |
| 英语能力良好 | `【待补：证书或成绩】` | 暂无 | 不能直接写入成稿 | 待补充 |

### 输出与交接

`/asu` 交给 `/resume` 的内容应只有两类：

1. 已确认、可以直接写入简历的表述；
2. 明确带有 `【待补】` 的字段。

不得把“待补充”自动改成更好看的事实。

## 4. `/resume`：生成可编辑简历

### 输入

- 已确认的一句话定位；
- 教育、项目、开源贡献和技能内容；
- 目标岗位为 AI 应用工程师实习生；
- 单页、无照片、稳妥风格。

### 处理目标

`/resume` 根据岗位和内容密度选择 A4 单页结构，生成真正可编辑的 HTML，而不是整页截图。

推荐信息顺序：

1. 姓名、联系方式、目标岗位；
2. 教育背景；
3. 会议纪要项目；
4. 已合并开源贡献；
5. 技术技能；
6. 待确认字段不进入正式 PDF。

导出前完成 print-preview QA：

- A4 仅 1 页；
- HTML 文本可选中和编辑；
- 工具栏不进入打印结果；
- 长项目标题、邮箱和链接不溢出；
- PDF 没有浏览器页眉页脚或多余空白页。

### 输出与交接

```text
林舟_AI应用工程师_简历.html
林舟_AI应用工程师_简历.pdf
```

PDF 用于投递，HTML 保留为可编辑源文件。每次修改定位或项目证据时生成新的简历版本，不直接覆盖无法追溯的旧版本。

## 5. `/interview`：把简历问穿

### 输入

- 上一步生成的 `林舟_AI应用工程师_简历.pdf`；
- 目标岗位：AI 应用工程师实习生；
- 要求：从最高风险的主张开始，一次只问一个问题，答得含糊就继续追问。

### 处理目标

`/interview` 从简历中提取需要验证的 Claim，预测高概率面试问题，并通过连续追问检查林舟是否真的讲得清个人职责、技术实现、指标口径和项目边界。它不替林舟编造答案，只标记哪里讲不透。

#### 高风险主张与预测问题

| 简历主张 | 预测问题 | 追问发现 |
| --- | --- | --- |
| 三类结构化字段输出 | 提示模板是怎么设计的？解析失败怎么处理？ | 能讲清模板结构，讲不清失败兜底的边界条件 |
| 3 名课程组成员演示验证 | 用户量口径是什么？收到了什么反馈？ | 诚实说明是课程演示，无公开用户量，不作引申 |
| 已合并开源文档贡献 | 这个 PR 解决了什么问题？怎么验证的？ | 能完整复述问题、diff 和从空目录验证的过程 |

#### 复盘结论

- 高风险表述：「熟悉大模型应用」被追问到训练或 AI Infra 会露馅，建议保留但附能力边界说明；
- 知识缺口：API 超时、限流与失败重试的处理方式，建议先补一次实验，再决定是否保留「失败结果的人工修订入口」的表述强度；
- 需要补证据：「3 名成员试用」缺少反馈记录，面试中只作定性说明，不引申为用户验证。

### 输出与交接

- 面试问题清单、追问记录和掌握度复盘；
- 两处修改建议回传 `/asu` 复核、由 `/resume` 生成新版本：为「熟悉大模型应用」补充边界、暂缓重试相关表述；
- 面试准备不生成新的经历，只让已有表述经得住追问。

## 6. `/offer`：记录投递和下一步

### 输入

假设林舟使用上一步简历开始投递，收到三类通知：

- 示例科技：申请已收到；
- 星云智能：在线测评邀请；
- 远航数据：邮件内容无法确认是否进入筛选。

### 状态整理

| 日期 | 公司 | 岗位 | 状态 | 下一步 | 证据 |
| --- | --- | --- | --- | --- | --- |
| 2026-09-10 | 示例科技（虚构） | AI 应用工程师实习生 | 已投递 | 等待后续通知 | 自动回执 |
| 2026-09-11 | 星云智能（虚构） | AI 应用工程师实习生 | 测评中 | 9 月 14 日前完成测评 | 测评邀请 |
| 2026-09-12 | 远航数据（虚构） | AI 平台实习生 | 待确认 | 核对邮件正文或招聘网站 | 信息不足 |

普通自动回执只证明“已投递”，不能推断为筛选通过；信息不足时保留“待确认”。

### 输出

- 可搜索、筛选、编辑的 `application-tracker.html`；
- 本次新增与状态变化摘要；
- 下一步行动清单；
- 可导出的 CSV/JSON 备份。

## 8. 这个案例没有做什么

- 没把课程 Demo 写成生产系统；
- 没把文档 PR 写成核心模型贡献；
- 没编造用户量、准确率、延迟或收入；
- 没把待确认英语成绩放入正式简历；
- 没在用户确认前执行 fork、push 或创建 PR；
- 没替林舟编造面试答案，只标记讲不透的知识缺口；
- 没把虚构案例中的人物、公司和链接当成真实经历。

这个流程的价值不在于把每一项经历写得更大，而在于让岗位定位、公开证据、简历文件和投递状态使用同一套真实边界。
